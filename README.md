# regexlab · 正则引擎解剖台

> 把一条正则拆成语法树、编译成 ε-NFA 画出来，再用三种自己写的引擎跑同一个输入串，对比步数与耗时。

[English](README.en.md) | 中文

## 这是什么

解析器是递归下降写的，支持分组、字符类、锚点、转义和 `{n,m}` 计数；编译走 Thompson 构造，靠补丁表回填那些悬空的跳转。状态图是手写 SVG：边是二次贝塞尔曲线，标签沿法线外移，当前活跃状态集合随输入实时高亮。匹配有三种实现——并行 NFA 模拟（ε-闭包 + 每步把起点闭包并回集合，以此实现包含匹配）、子集构造出的 DFA（状态就是 NFA 的状态集合，每个字符只查一次表），以及一个故意不做记忆化的递归回溯器（15 万步上限，用来现场演示指数回溯）。页面上可以单步或播放整条输入，看活跃集合怎么收缩和膨胀。全部逻辑在浏览器里跑，没有调用 `RegExp` 做匹配，只用它交叉验证：2080 个随机用例结果完全一致。

## 功能

- 递归下降解析器：分组 / 字符类 / 锚点 / 转义 / `{n,m}` 计数，产出可视化的 AST
- Thompson 构造 ε-NFA，SVG 手绘状态图，活跃状态与消耗的边实时高亮
- 并行 NFA 模拟：ε-闭包 + 每步注入起点闭包，实现包含匹配，逐字符可单步回放
- 子集构造 DFA 转移表，含注入版本；遇到 `^`/`$` 明确说明为何跳过
- 朴素回溯器：AST → 指令序列 → 递归执行，15 万步上限，现场演示指数回溯
- 三引擎步数与 `performance.now()` 耗时对比，横轴取对数，并与浏览器 RegExp 交叉验证
